# O017 semantic and assessment wrapper v1

This directory adds an enforceable, locale-neutral model beside the preserved
O017 backend. It does not replace `schema.json`, `records.jsonl`,
`relations.csv`, or `relations-ledger.csv`.

## Files

- `semantic-wrapper-v1.schema.json` is a JSON Schema Draft 2020-12 union for
  learning outcomes, competencies, assessments, rubrics, criteria,
  submissions, attempts, evaluators, evidence, results, credential states,
  and localized text.
- `semantic-wrapper-v1.records.jsonl` contains neutral definitions and
  templates. It contains no learner instance and makes no completion claim.
- `semantic-wrapper-v1.localizations.jsonl` contains all human-language text,
  with explicit `locale: id-ID` and `language: id`.
- `semantic-wrapper-v1.relations-ledger.csv` is a separate append-only ledger.
  Its first 1,636 issued rows are the core semantic graph; later rows append
  crosswalks to the independently produced `O017-WRAP-*` delivery model.
- `semantic-wrapper-v1.baseline.json` freezes the byte, ID-set, and issued-
  relation-map identities of the preserved backend before this wrapper.
- `semantic-wrapper-v1.dataset.json` inventories generated bytes, counts,
  frozen inputs, claim boundaries, and delivery crosswalks.

Renderer fragments never identify semantic entities. Every `fragment` occurs
inside a locator object with `canonical_identity: false`. Neutral assessment
IDs are crosswalked to the delivery model's neutral `O017-WRAP-A01` through
`O017-WRAP-A05` IDs; no fragment is used as a relation endpoint.

The semantic stream contains definitions and templates only. Actual learner
packages must receive new IDs and validate against
`delivery/schema/o017-delivery.schema.json`. Calibration artifacts remain
`calibration_only`, are not credit eligible, and are not evidence that a
learner or community transaction exists.

## Rebuild and validation

From the course root:

```text
python scripts/generate_semantic_wrapper.py --check
python scripts/validate_semantic_wrapper.py --write-qa
```

The generator verifies the preserved backend before computing anything. It
may refresh deterministic materialized views, but it will only append to its
own relation ledger when every existing row is an identical prefix. Any
correction to an issued relation requires a new wrapper version and an
explicit supersession record; the old row must remain.

The validator meta-validates the schema, validates every JSONL record,
replays all generated bytes, resolves every relation endpoint and locator,
checks all five delivery/calibration crosswalks, and runs negative schema
tests. Its deterministic receipt is `qa/SEMANTIC_WRAPPER_QA.json`.

Release integration must include the six machine wrapper files plus this
guide, the two wrapper scripts, the QA receipt, and the referenced `source/wrapper` and
`delivery` package. Existing manifests may be extended by the release owner;
the four preserved backend files must remain byte-identical to the baseline.
